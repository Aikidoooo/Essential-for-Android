# HyperOS向け配布と容量

XIAOMI版はarm64-v8a専用、applicationIdは`jp.essential.app`で共通です。同じ配布署名で上書き更新し、通知ログ・設定・保存ファイルを維持します。メーカー判定にはXiaomi / Redmi / POCOを使用し、OSの保護や省電力設定を自動変更しません。

64bitでは既存のFFmpegKitを使います。使わないyoutubedl-androidの`libffmpeg.zip.so`だけをAPKから除き、Python・QuickJS・FFmpegKit・OCR・ONNXと32bitのFFmpegは残します。Pythonが実ファイルを必要とするため、ネイティブライブラリの展開方式は維持します。

通知記録が途切れる場合は通知ログ画面の「HyperOSのバックグラウンド設定」で自動起動を確認できます。機種によって専用画面が開けない場合はAndroid標準のアプリ情報を開きます。バッテリー制限の変更は利用者の任意です。通知アクセス許可は別の設定で、許可済みならその設定カードを隠します。

低メモリ端末ではホームのガラスシェーダーを使用せず、ガラスのグラデーションと操作アニメーションを維持します。通常端末ではシェーダー効果を再利用します。既存の希望FPS設定は同じ解像度の実際の対応リフレッシュレートから選び、画面復帰時に適用し直します。OSの省電力による上限は解除しません。

配布CIはAPK本体とCPU別インストール容量の概算を検査し、`SIZE_REPORT.json`を添付します。計算はAPK＋圧縮ネイティブライブラリの展開容量＋64MBのデータ枠です。利用者の保存メディア・keepログ等は増えるため、無制限に保存しても合計400MB以下という保証ではありません。容量条件を超えるuniversal版は0.6.5では配布せず、全4CPU別のAPKを用意します。

検証範囲：Androidエミュレーターの操作・動画結合・容量、単体テスト、Lint、Release APK。HyperOS実機の自動起動画面・バックグラウンド持続性・フレーム時間は未確認です。
