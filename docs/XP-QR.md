# XP配布QR（オフライン方式）

管理者のWindows PCで署名付きQRを発行し、EssentialのQRスキャナーで読み取って「XPを受け取る」を押します。通常のQR作成画面でXPを発行することはできません。署名済み文字列はURLではないため、通常のカメラでWebページやEssentialを自動起動しません。Essentialの読み取り処理がXPとして扱います。

## 発行

`D:\#AI開発\Android\Essential\Essential-XP発行者` に生成ツールを配置しています。`Issue-XpQr.cmd` をダブルクリックし、XPと有効日数を入力すると発行できます。Windows PowerShellで以下を実行する方法もあります。

```powershell
& "D:\#AI開発\Android\Essential\Essential-XP発行者\New-XpQr.ps1" -Points 1200 -Days 30
```

Pointsは1〜1,000,000、Daysは1〜366です。指定しない場合の期限は30日です。出力は同じフォルダーの「配布QR」にPNGと署名済みテキストで保存されます。実行するたびに異なる配布IDが発行されるため、同じポイント数でも別QRとして受け取れます。既存QRの期限・ポイントを書き換えると署名が無効になります。

Java 23とZXing 3.5.3を使用します。このPCのJava配置を変更した場合はスクリプト内のjava.exeパスも更新してください。初回初期化用Initializeは実施済みです。再初期化や公開鍵の入れ替えは配布済みQRを無効にするため、通常は実行しません。

## 署名と鍵管理

RSA 3072bit・SHA-256・PKCS#1 v1.5で、固定バージョン・対象アプリ・ランダムUUID・XP・発行時刻・期限を署名します。APKは固定公開鍵だけを含み、QRから鍵や署名方式を選ばせません。URL-safe Base64の正規表現・正規エンコード・長さ・各値の範囲も検査します。

秘密鍵は`D:\#AI開発\Android\Essential\Essential-XP発行者\秘密鍵\issuer.dpapi` に保存します。DPAPI CurrentUserで暗号化しているため、通常は同じWindowsユーザーだけが復号できます。同じアカウントで動く不正プログラムまで防ぐものではありません。秘密鍵をGit・APK・配布先へ含めないでください。この鍵を失うと現在の公開鍵に対応した新規QRを発行できなくなるため、Windowsアカウントを含む復元可能なバックアップを管理してください。

## 一回だけの受取

アプリの保存領域が保持される間、同じ配布IDは一回だけ受け取れます。署名と期限は受取時に再検証し、使用済みIDとXPを同一のSharedPreferencesコミットで保存します。複数同時受取は共通ロックで直列化し、期限切れ後もIDを削除しません。受取履歴の上限は100,000件で、上限到達時は新規受取を拒否します。

## 制約

この方式はユーザーの選択によりサーバーを使いません。QRコピーの別端末での受取は許容します。再インストール・データ削除・過去バックアップ復元では再受取できる場合があります。端末時計の巻き戻しによる未受取QRの期限回避、root・アプリ改造・保存データ操作、外部アプリでの独自解釈、配布QRの横取りや発行者PCの侵害は防げません。人の本人確認や正規APKの遠隔証明は行いません。署名は配布元と内容の正当性を証明し、受取者本人を証明するものではありません。

全端末を通して一回だけの使用、本人認証、鍵の即時失効、信頼できる期限判定には、認証済みサーバーと共有台帳、必要に応じたアプリ証明を追加する必要があります。

## UIとモーション

受取カードは既存WidgetGlass、ProgressiveWidget、WidgetButtonを再利用します。押下倍率0.98、Spring減衰0.86・剛性650は共通WidgetGlass.ktで調整できます。受取中は連打を無効化し、署名検証と保存はIOスレッドで処理します。既存のURL・写真・カメラ読み取りを維持します。

## 検証結果（2026-10-13）

Debug本体・テストAPKビルド成功。単体テスト3件で正規署名・改ざん・別鍵・不正形式・対象アプリ違い・範囲外・期限切れを確認。最新APKをemulator-5554へデータ保持で再インストールし、計5件の端末試験成功。生成PNGの復号、受取UIとXP加算、同時12要求で一回だけ付与、ストア再生成後の再使用拒否、改ざん拒否、既存QRの復号・保存契約・入力検証を確認。

端末試験は独立したSharedPreferencesを使い実ユーザーのXPを変更しません。描画画像はbuild/xp-voucher-card.png、ビルド証跡はbuild/xp-qr-final-build.log、端末試験はbuild/xp-qr-device-tests.logに保存。実機カメラ・FPS・電池消費・公開版APKは未検証です。

端末試験用の署名済みfixtureは実際の期限を持ちます。期限経過後は発行者PCで1200XPのQRを再発行し、対応するtxtとpngをapp/src/androidTest/assets/xp-voucher-fixture.txt・xp-voucher-fixture.pngへ更新してから再実行してください。単体テストは専用鍵と固定テスト時刻で独立して実行できます。

署名APIの仕様は[Java Signature公式資料](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/security/Signature.html)を確認しています。
